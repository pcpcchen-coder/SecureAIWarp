# 08 延伸構想

核心設計之外，值得進一步探索的點子。依「對使用者的價值 ÷ 實作難度」粗略排序。

## 1. 試駕模式
接收者在給出真實資料與金鑰之前，先讓工具在**全是誘餌**的環境裡跑一輪：假的文件夾、假的金鑰、假的聯絡人，每一份都帶有可追蹤的標記。

試駕結束後得到一份報告：「它讀了這 12 個檔案、嘗試連到這 3 個主機、誘餌標記出現在送往 X 的請求中」。

- 與側錄模式是同一套機制，只是執行者換成接收者。
- 讓「不信任作者的宣告，自己看一次」的成本降到幾分鐘。
- 限制：只能看到試駕期間觸發的行為，刻意延遲發作的惡意行為看不到——所以它是補充，強制模式才是主體。

## 2. 後悔藥（覆寫層 + 可逆操作）
對不讀程式碼的使用者，最實際的保護是**做錯了能復原**。

- **檔案**：寫入先落在覆寫層，結束時顯示變更清單（新增 3、修改 12、刪除 0），使用者按下套用才生效；或直接套用但保留快照可一鍵還原。
- **對外的副作用**（寄信、發文、付款）無法復原，因此在同意代理中一律標示為「不可逆」，與可逆操作有明顯的視覺區別。
- 更進一步：把工具的動作分成可逆與不可逆兩類，政策上對前者寬鬆、對後者嚴格，比一律詢問更不擾人。

## 3. 保險絲
不依賴理解意圖、只看數量的熔斷器：

| 保險絲 | 觸發條件示例 |
| --- | --- |
| 花費 | 單日模型費用超過上限 |
| 刪除 | 短時間內刪除或覆寫的檔案數超過門檻 |
| 外傳 | 上傳流量遠超歷史基準 |
| 迴圈 | Agent 步數或相同工具呼叫重複次數超過上限 |
| 時間 | 執行時間超過預期 |

熔斷後暫停應用並通知人，而不是直接終止——保留現場以供判斷。

## 4. 權限衰減
宣告中的授權若長時間沒有被使用（帳本可查），核心提示可以移除。權限只增不減是常態，這個機制讓它能自然收斂，也讓下一版的標籤更乾淨。

## 5. 分權式多 Agent 殼
把「致命組合」拆到不同的殼裡。資料外洩需要同時具備三件事：接觸敏感資料、接觸不受信任的內容、對外傳送的能力。為多 Agent 系統配置殼時，檢查器可以加一條結構性規則：**任何單一殼不得同時具備這三者**，否則列為例外。

這把提示注入從「偵測問題」變成「架構問題」。

## 6. 測試缺口回饋
試穿階段被擋下的行為、以及靜態盤點發現但側錄沒觸發的行為，正好是**測試沒涵蓋到的功能清單**。把它回饋給開發 Agent 補測試，殼就不只是事後加上的防護，而成為開發迴圈的一部分：

```
開發 Agent 寫功能與測試 → Fitter 側錄與試穿 → 回報未涵蓋行為 → 開發 Agent 補測試 → …
```

## 7. 標籤即徽章
在應用的 README 或商店頁面顯示由封籤產生的徽章（信任等級 + 風險等級），連結到完整標籤。讓「有沒有裝殼」成為使用者挑選工具時看得見的差異，形成採用的誘因。

## 8. 組織政策
機器可讀標籤 + 一份組織政策檔，讓 IT 從「逐案審查」變成「設定條件」：

```yaml
# 示意
allow_if:
  trust_level: ">= L2"
  secrets: all_gate_only
  egress_hosts: subset_of(approved_hosts)
  exceptions: none
otherwise: require_review
```

符合條件的工具員工可以自行安裝；不符合的才進人工審查。這可能是殼在企業內最直接的價值。

## 9. 行為指紋共享
同一個 Bundle 在許多接收者端執行時，各自的帳本可以（在使用者同意下）回報匿名的行為摘要。若某版本在少數環境出現其他環境沒有的對外連線，就是值得調查的訊號。這能補上試駕模式看不到延遲行為的缺口，但涉及隱私與基礎設施，屬於遠期構想。

## 10. 殼的自我揭露
殼本身也是「給別人用的工具」，應該適用同一套標準：Warp Core 要有自己的標籤、相依清單、可重現建置與獨立驗證。安裝核心時顯示它需要的主機權限與原因。
